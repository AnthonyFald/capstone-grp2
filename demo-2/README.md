# Demo 2 — Daily construction report review

Use daily site updates from supervisors, superintendents and trades: work completed, inspections, problems, instructions, deliveries and next steps. Each spreadsheet row or JSON object is one report from one author/trade/date. The main example follows the team's supplied **Simulated Daily Reports CSV - Daily Reports.csv**, with ten synthetic Room B104 reports. Start with **Use sample reports** or download the [sample CSV](data/sample-daily-reports.csv) / [sample JSON](data/sample-daily-reports.json), then upload it to test the workflow. These downloads contain the 18 source fields and exclude the supplied completeness/answer annotations. [Source provenance](docs/source-update-20261022.md) records the changes and preserves earlier inputs; reference definitions were not changed to fit predictions. The [upload guide](docs/upload-guide.md) describes required columns and limits. PDF, Word, photos and audio are not supported imports.

Select **Analyze reports**, read each neutral **Review question**, check its dated source timeline, and choose Keep/Correct/Reject. The question and suggested status are AI interpretations. Status applies only to that concern: physical completion does not close a missing record, uncertain decision receipt or unfinished quality task. Repeated candidates are linked in a shared concern list and consolidated without rewriting their source quotations; genuinely independent aspects remain separate. This mechanism must still be checked for missed merges or inappropriate merges.

Download the **TXT review** for a readable record of the questions, scoped statuses, dated quotations and reviewer decisions/notes. Rejected findings remain labelled in that download. Use the findings CSV for spreadsheet review or the full JSON to retain inputs, original predictions, corrections and analysis details. The readable TXT is a report output, not an import format or a substitute for the full audit record. Advanced model/device settings and research tools are collapsed; normal review does not require scoring, timers or batch experiments.

The source-based pipeline constructs an exact sentence inventory and asks the local model to select/group evidence, reconcile later updates, and check omitted concerns. Focused checks inspect remaining tasks, historical work/delivery changes and opposing inspection/release accounts, followed by materiality verification. An independent source review rechecks proposed dismissals of candidates; its original decisions and any restorations remain in the record. Shared concern consolidation audits independent subjects, preserves member evidence and checks the narrow scope of each final status. The app renders original text and its report author/date, without generating causes, impacts, owners or deadlines. Type, question wording, status, relevance and grouping remain fallible model interpretations. A valid quotation does not prove its interpretation. Exact repeated citation IDs are treated as a set with a repair trace; nonexistent, foreign or stale pointers remain invalid. An unresolved validation conflict rejects the result.

The installed **Qwen 3.5 27B** model is preferred for quality; Qwen 3.5 9B and browser 9B/4B are lower-memory alternatives under Advanced settings. Native models use Ollama plus `node scripts/serve-local-ai.mjs` on loopback. All report processing stays on device. Initial model/library downloads need internet. See [Windows and Apple silicon setup](docs/local-setup.md). Apple silicon runtime compatibility is retained; measured inference uses the RTX 5080 only.

Included A/B and additional D cases informed development. C/E are routine-work controls. F was authored separately with references withheld from the implementing agent until the recorded v17 freeze and completed evaluation. Its earlier v15 attempt was canceled before completed predictions. A new G case supports checking the consolidation revision; its source/reference access and evaluation sequence must remain explicit. Across A–G there are 44 synthetic reports and 42 reference concerns. Case authors inherited project context, so this is agent-assisted evaluation requiring independent human validation. Scoring uses original predictions, counts partials as misses, and classifies unsupported outputs and duplicates separately. Revised results are reported only after actual inference and scoring. No human productivity observations were invented. See [results](docs/results.md), [protocol](docs/protocol.md), [data review](docs/data-review.md) and [collection guide](docs/collection-guide.md).

Source inventory, pointer validity, short-citation idempotence, audit edits, stale-state guards, exports and local request isolation have regression coverage. Model quality is assessed with real retained inference outputs, not unit-test mocks.

A final requirement check reviews action and schedule passages, including compound conditions inside already-cited sentences. A separate critic checks that draft before it can change the findings. Before a new source quotation enters a finding, a further check reviews that source on its own against the question's actual subject, task and timing; sharing an issue category is insufficient. An unmatched task becomes a separate source-backed candidate for the concern review. Open requirements are shown with their complete original quotation; independently actionable tasks remain separate. A report reminding readers of completed work is distinguished from evidence that closes an earlier pending task. The full JSON retains the original proposals, corrections and final decisions. Links to quotations already present remain unverified metadata; they do not add factual content. All model judgments still need semantic review.

A final product-change check separately reviews proposed new quotation associations and new concerns against the original question and full dated history. Ambiguous or unsupported changes are withheld for manual review. Original findings and their evidence remain preserved; the full record retains the proposals, review decisions and abstentions. The page and TXT download show a short notice when proposed additions could not be verified. An abstention does not establish that a task is routine, closed or absent.

For retained revision-18 run files, use `node demo-2/scripts/verify-consolidation.cjs --paths RUN.json --out AUDIT.json`. Multiple input paths are accepted. The auditor checks exact quotations and source provenance, concern identities, complete candidate/merge accounting, preserved evidence, explicit removal reasons and readable TXT quotation coverage. It reads no reference answers and prints only audit metadata/counts/errors. A pass establishes mechanical preservation, not correct merge semantics, issue coverage or suggested statuses; separate provisional scoring and independent human review are still needed.

Freeze manifests distinguish original file-byte hashes (`files`) from UTF-8/LF transport hashes (`canonicalUtf8LfFiles`). Retained benchmarks record the actual Windows file bytes used at execution; publishing through Git may normalize line endings. Compare a published LF file with its canonical transport hash, while preserving the original benchmark hash. Normalized report hashes cover `JSON.stringify(DailyCore.reports(input))`; replay verification compares each complete generated request, independently of the source file's transport line endings.
