Contextual meeting notes v4 — development and evaluation

The model remains Qwen3.5 9B, quantized for local WebGPU. No fine-tuning, model
replacement, remote inference or new download is required for existing users.

The first stage works through consecutive small groups of source turns, producing
a structured inventory of tasks, owners, exact deadlines, conditions, work scope,
project milestones and unresolved questions. Every call receives the complete
transcript for context, including later corrections. The focused excerpts cover
every source turn once. The final stage reviews each numbered inventory fact: it must cover it in the final notes or explicitly explain its omission.
It also checks the original transcript for missing facts. Dated physical work
belongs in schedules; calls/emails/submissions belong in actions. The prompts
separate follow-up messages and preserve prerequisites from earlier turns.

Both responses must be complete structured output. Invented source references,
truncated responses and missing inventory assessments fail validation. This is
coverage bookkeeping, NOT proof that the model correctly understood each fact.
The audit can still make a bad omission decision or miss a fact in both passes.
No automatic semantic accuracy claim is made.

Owner normalization recognizes unique short/full speaker names and attendee
metadata. Role suffixes do not invalidate a name. Ambiguous first names remain
unassigned and flagged. A person must still be supported in the cited source;
a company is not automatically replaced with its manager. Original evidence
is retrieved verbatim. Names and deadline checks establish textual provenance,
not whether the assignment/deadline belongs to that particular task.

Timing
Note generation has no elapsed-time cutoff. It continues until completion,
cancellation, or an error. A live minutes:seconds timer runs during inference
and stops when the run ends. Model setup and audio timing remain separate.

The browser evaluator uses the actual worker in an isolated Chrome profile.
Public model files download once; transcripts never leave the local runtime.
--temperature applies to the structured extraction and final review (default 0.1).
Both stages use complete structured output; there is no free-form thinking draft.
Default fictional
fixtures are tests/fixtures/note-quality-v3.json. Reports retain inventory, final
output, source references, code hashes and timings for human review. Debug
inventories are not included in user exports. Keep private reports out of Git.

Measure factual correctness and completeness separately. Freeze the reference
checklist before inspecting new outputs, count each required fact only once,
and report duplicates, owners, timing and unsupported certainty. Test clean
written scripts to isolate extraction from transcription. Repeated runs and
independent meetings are needed before claiming a general accuracy improvement.

The supplied private scripts and baseline exports are used only on the local
machine and are excluded from this repository. Historical v3 results remain in
note-quality-v3-results.json; they describe the previous pipeline, not this one.
Notes may still miss information or misread conditions. Valid citations and a
complete coverage ledger do not eliminate the need to review generated notes.
