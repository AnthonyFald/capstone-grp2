Contextual meeting notes v4 — development and evaluation

The model remains Qwen3.5 9B, quantized for local WebGPU. No fine-tuning, model
replacement, remote inference or new download is required for existing users.

The model reads the full meeting separately for follow-ups, scope/restrictions,
physical milestones, and unanswered questions. Long speaker turns are formatted
as smaller sentences and coordinated promises, keeping an exact mapping back to
the original source lines. This changes presentation, not the original transcript.

Potential commitment clauses each receive an explicit action review, with an
additional-actions list for commitments without a pattern cue. Candidates are not
automatic assignments: the model must reject completed work, canceled tasks,
unaccepted offers, incidental movements and recaps. Full context remains available
for later answers, reassignment and deadline changes. The accepting speaker owns
a requested task; the requester is not automatically its owner. A deadline appearing only
in a later independent task in the same turn does not date an earlier task.

Each milestone receives a separate full-source check of its work, timing and
supporting lines. Qualifying timing statements are copied verbatim into the note
when selected, rather than asking the model to invent a dependency summary. The
model can still select incomplete or irrelevant evidence, and the timing-context
filter can miss qualifications; this is not a guarantee of complete dependencies.
Administrative submissions and undated milestone placeholders are filtered out.
All generated sections must be complete and cite real original source lines.
These checks establish provenance, not semantic correctness. Human review is
still required for omissions, duplicate facts, unsupported certainty and wording.

Owner normalization recognizes unique short/full speaker names and attendee
metadata. Role suffixes do not invalidate a name. Ambiguous first names remain
unassigned and flagged. A person must still be supported in the cited source;
a company is not automatically replaced with its manager. Original evidence
is retrieved verbatim. Names and deadline checks establish textual provenance,
not whether the assignment/deadline belongs to that particular task.

Timing
Note generation has no elapsed-time cutoff. It continues until completion,
cancellation, or an error. A live minutes:seconds timer runs during inference
and stops when the run ends. Model setup and audio timing remain separate.

The browser evaluator uses the actual worker in an isolated Chrome profile.
Public model files download once; transcripts never leave the local runtime.
--temperature applies to the section extraction (default 0.1).
Each call returns complete structured output; there is no free-form thinking draft.
Default fictional fixtures are tests/fixtures/note-quality-v3.json. Reports retain section and final
output, source references, code hashes and timings for human review. Internal review
metadata is not included in user exports. Keep private reports out of Git.

Measure factual correctness and completeness separately. Freeze the reference
checklist before inspecting new outputs, count each required fact only once,
and report duplicates, owners, timing and unsupported certainty. Test clean
written scripts to isolate extraction from transcription. Repeated runs and
independent meetings are needed before claiming a general accuracy improvement.

The supplied private scripts and baseline exports are used only on the local
machine and are excluded from this repository. Historical v3 results remain in
note-quality-v3-results.json; they describe the previous pipeline, not this one.
Notes may still miss information or misread conditions. Valid citations and a
structured extraction do not eliminate the need to review generated notes.
