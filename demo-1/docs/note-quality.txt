Contextual meeting notes v3 — development and evaluation

Qwen3.5 9B reads the complete meeting in two passes. First it creates a bounded
internal working record of tasks, owners, deadlines, later changes, restrictions,
conditional milestones and unresolved questions. The second call independently
checks that record against the complete transcript and returns four separate
lists: actions, decisions, schedules and unresolved questions. Neither call
filters the meeting down to phrase-matched action candidates.

The internal record is never displayed/exported and may end at its reasoning
allowance. The final pass reads the whole source again. A truncated final response
fails visibly. Only complete final notes with valid references are displayed.
Schedules have their own section and can be marked tentative. These are model
selection and inference/prompt changes; model weights are unchanged.

Source line numbers must exist. Original wording is retrieved verbatim and retained
in the UI and exports. Owners/deadlines must occur in cited evidence. This checks
provenance, not whether the model interpreted the evidence correctly. Every note
still requires human review. The pipeline can omit a follow-up, misclassify scope,
lose a qualification, or repeat an outdated proposal; it does not certify accuracy.

Timing
The browser terminates note generation at a five-minute processing budget.
Known processing time from an applied audio transcript is deducted. Model setup
and user review are excluded when separately measurable. The companion reports
processingSeconds separately from modelSetupSeconds. Older imported transcripts
use elapsedSeconds conservatively. Audio processing itself depends on recording
length/hardware and is not interrupted by the browser's note timer. A recording
that consumes the budget cannot proceed to AI notes without a shorter new run.
The budget is not an assurance that every input will complete successfully.

Transcription
Whisper Small is the accuracy default; Base remains available. A construction
vocabulary and optional user spelling hints are passed as initial_prompt.
They are hints, not automatic transcript replacements or verified identities.
No original user audio was available for this iteration: supplied ASR transcripts
can test note extraction but cannot establish improved recognition accuracy.

Checks
node --test demo-1/tests/*.test.cjs tests/*.test.cjs
python -m unittest discover -s demo-1/local-audio -p "test_*.py"
python demo-1/scripts/evaluate-notes.py --model Qwen3.5-9B-q4f16_1-MLC

The real-browser evaluator uses the actual worker and an isolated Chrome profile.
--temperature selects 0.1 (default), 0.3 or 0.7 for final extraction only; the
internal reasoning pass stays at 0.7. Default fictional development fixtures are
tests/fixtures/note-quality-v3.json. Reports retain actual final model output,
source references, code hashes, runtime and criteria for qualitative review.
Internal reasoning is not exported. Keep private transcripts/reports out of Git.

Evaluate supported facts, missed key information, correct owner/deadline pairs,
false commitments and the time needed to review/correct results. These development
fixtures influenced prompt choices and are not an independent accuracy benchmark.
No 90% accuracy or guaranteed five-minute success claim is made. Future evaluations
should keep independently authored meetings held out from prompt changes and
repeat runs to measure variability.

Selection and limitations
Several larger/faster configurations were rejected after actual browser runs:
parameter count and speed alone did not predict correct assignments and dates.
Longer unrestricted reasoning could use the entire budget without producing final
notes. The selected approach limits its initial reasoning to reserve time for the
final source-checked output. See note-quality-v3-results.json for measured results
and remaining errors, rather than treating an additional model pass as proof.

Supplied transcripts were used only for local development checks and are not in
this repository. Public results use fictional fixtures and qualitative assistant
review, not a blinded accuracy score. The historical note-quality-results.json
and verification.json describe earlier checks and are not current performance
claims. Notes can inherit transcription errors; review the transcript first.

The published snapshot runs three selected regressions from the eight available
fictional fixtures. The first two retain the key facts but repeat an item across
categories. The longer case omits important follow-ups/conditions and distorts
a ventilation restriction. The raw output and those findings are retained;
completion status is not a semantic pass or an accuracy percentage.
